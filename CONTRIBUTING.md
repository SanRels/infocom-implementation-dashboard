# Правила командной работы

## 1. Ветвление Git
- `main` — стабильная версия проекта.
- `develop` — общая ветка разработки.
- `feature/<task>_<description>` — ветки для выполнения задач.

## 2. Именование коммитов
Используем формат Conventional Commits:

`<type>(<scope>): <short description>`

Примеры:
- `docs(readme): add project overview`
- `feat(backend): add health endpoint`
- `feat(frontend): add homepage`
- `chore(devops): add docker compose`

## 3. Порядок работы
1. Создать рабочую ветку от `develop`.
2. Выполнить задачу и проверить изменения.
3. Сохранить изменения коммитом.
4. Отправить изменения в GitHub.
5. Создать Pull Request в `develop`.
6. Назначить проверяющего и учесть замечания.
7. Объединять изменения после проверки.

## 4. Проверка кода
- Pull Request должен содержать описание изменений и ссылку на задачу.
- Перед слиянием необходимо проверить изменения.
- Замечания проверяющего нужно исправить до слияния.
